## RapidGo V4 · Riesgo transaccional — v1.0.0 (versión final)

**Equipo 9:** Esteban Rueda · Oscar Becerra · Karol Perez — Línea de Profundización I (Big Data), UCundinamarca

Flujo de datos de punta a punta que detecta comportamientos atípicos en los pagos de RapidGo:
productor → Kafka → Spark Structured Streaming → Data Lake (raw/processed/curated) → Airflow (calidad y reporte),
con pruebas automáticas y GitHub Actions como quality gate.

### Qué incluye
- Productor Python con clave `id_pedido`, `acks=all`, idempotencia y ~5 % de pedidos anómalos.
- Kafka KRaft, topic `rapidgo.v4.pagos.intentos` con 3 particiones (ADR-001).
- Spark: 5 consultas continuas con checkpoint; indicadores K1–K4 por minuto; alertas MULTIPLES_INTENTOS y
  SENALES_COMBINADAS; marca de agua de 2 minutos (ADR-002).
- Airflow 3.3.2: DAG de 6 tareas con reintentos, XCom, chequeos de calidad, alertas agrupadas por pedido,
  cuarentena de mensajes dañados y reporte diario (ADR-003).
- 94 pruebas; CI con `validar`, `validar-dag` y `quality-gate`; este release lo publicó `release.yml` solo
  después de pasar el quality gate y de construir las imágenes de Docker.

### Resultados de la ejecución final (2026-11-13)
- 10 841 mensajes en 19 min (33.1 / 33.4 / 33.5 % por partición), 0 huecos de offsets.
- 534 eventos de riesgo (4.97 %); 541 alertas A2 agrupadas en 240 pedidos (−55.6 %).
- Flujo completo desde cero con `scripts/prueba_e2e.sh --limpio`: 4 min 49 s.
